Does one <audio> element keep user activation across src changes?

This reproduces components/lessons/lesson-player.tsx exactly: one <audio> element, played once from a real click, then re-pointed at a new src and re-played from a timer — with no further user gesture. That is what happens between narration steps when a lesson advances on onEnded.

Why this is not an automated test. The dev container does not enforce an autoplay policy — play() resolves with no user gesture even with --autoplay-policy=user-gesture-required and with Playwright's override stripped — so a playback test there passes trivially and means nothing. Chrome's public documentation does not say whether the policy is tracked per element or per document, and says nothing about src swaps. It has to be measured in a real browser.

How to run it: open this file in real Chrome and again in real Safari, on a normal machine, in a window you have not otherwise clicked around in. Do not use a headless or flag-modified browser. Then press the button once and listen for three rising tones.
